## 1. 目标

把「管道节点温度 / 流速 / 电伴热投切」三件事在一个面板里看清楚、控得住：

1. **看得见**：30 个节点的拓扑、实时温度与流速、异常判定、加热状态一眼可见；
2. **控得住**：本地阈值自动投切 + 云端手动开关加热（带时长），两种控制可切换；
3. **看得懂趋势**：除瞬时值外，提供温度 / 流速的**变化速率**，用于判断降温趋势与伴热效果；
4. **可管理**：管理员登录、节点基础信息入库、审计留痕、上传频率可调。

当前阶段为**纯前端模拟**（数据在浏览器内生成），已具备完整后端与数据库，只差真实设备接入。

## 4. 技术选型

| 层 | 选型 | 理由 |
|---|---|---|
| 运行时 | Node.js 24 | 内置 `node:sqlite`、`crypto.scrypt`，无需编译依赖 |
| HTTP | `node:http` 自建路由表 | 零框架、零依赖，部署时只有一个 node 进程 |
| 数据库 | MySQL 8（便携版）+ SQLite 兜底 | MySQL 便于后续多人/联网；SQLite 用于无法安装服务的机器 |
| 驱动 | `mysql2/promise`、`node:sqlite` | 统一封装在 `server/db.js`，业务代码不感知驱动 |
| 认证 | `crypto.scrypt` + 随机 token（存 sha256） | 不引入 JWT 库；会话可即时吊销 |
| 前端 | 原生 HTML/CSS/JS + Canvas | 单文件演进而来，无构建步骤，改完即刷新 |
| 部署 | 本机 bat 脚本 + Netlify 静态托管 | 现场可离线；对外预览零成本 |

## 6. 数据模型

### 6.1 admins

| 字段 | 类型 | 说明 |
|---|---|---|
| username | VARCHAR(32) PK | 账号，默认 `123456` |
| pwd_salt / pwd_hash | CHAR(24) / CHAR(88) | scrypt(base64) 加盐哈希 |
| role | ENUM('admin','viewer') | 权限分级的预留位 |
| status | TINYINT | 1 启用 / 0 停用 |
| must_change_pwd | TINYINT | 首登强制改密（当前 0） |
| last_login_at / last_login_ip | DATETIME / VARCHAR(64) | 登录审计 |

### 6.2 sessions

`token_hash CHAR(64) PK`（sha256，明文 token 只在 cookie 里）、`admin_id`、`expires_at BIGINT`（epoch ms，跨库可移植）、`ip`、`ua`。

### 6.3 nodes

| 字段 | 说明 |
|---|---|
| id | 节点编号 `N01`…`N30` |
| seq | 展示排序 |
| label / x / y | 名称、画布坐标（布局用） |
| dn_mm | 管径（决定流速阈值分档） |
| parent_id / edge_km / branch_kind / branch_dir | 拓扑关系：上级节点、与上级间距(km)、主干/分支/横向、伸展方向 |
| device_sn / installed_on / area / owner / note | 设备与运维信息 |
| t_on / t_off / flow_lo / flow_hi | 单节点阈值覆盖（留空则用全局规则） |
| enabled | 是否参与监测 |

> 注意：**不存「距起点」**。距起点由 `parent_id + edge_km` 链路实时累加得到，改拓扑后自动正确。

### 6.4 audit_logs

`admin_id / username / action / target / detail(JSON) / ip / ua / created_at`，登录、增删改节点、改密码、改设置均写入。

### 6.5 settings

`k VARCHAR PK / v JSON`，当前键：`uploadMs`（1000/2000/3000/5000/10000/30000）、`heatW`(25)、`tickMs`(2000)、`telemetryKeepDays`(7)。

## 8. 认证与会话

- 口令：`scrypt(N=16384, r=8, p=1, keylen=64)`，每账号单独 16 字节 salt，比较用 `timingSafeEqual`。
- 会话：32 字节随机 token（base64url）下发到 HttpOnly Cookie `sid`，库中只存 sha256；默认 8 小时过期，退出即删。
- 限流：同一 `username|ip` 5 分钟内失败 5 次锁定，返回 429 + `Retry-After`。
- 免密通道：`config.devLogin` 开关；任何人可进（当前阶段有意开放），**上线前必须置 false 并删除按钮**。
- 审计：登录成功/失败、节点写操作、改密、改设置全部落 `audit_logs`。

## 10. 判定与电伴热策略

### 10.1 异常判定

```
温度 < 1 ℃                 → 异常
流速 < 该管径下限           → 异常
```

| 管径 | 正常流速区间（m/s） |
|---|---|
| DN < 250 | 0.6 ~ 0.9 |
| 250 ≤ DN < 500 | 0.9 ~ 1.4 |
| 500 ≤ DN < 1000 | 0.9 ~ 1.6 |

### 10.2 参数

| 参数 | 值 | 含义 |
|---|---|---|
| T_START | 1 ℃ | 温度触发（低于） |
| T_STOP | 3 ℃ | 温度恢复（高于） |
| HOLD_ON_MIN | 3 min | 触发确认时间 |
| HOLD_OFF_MIN | 3 min | 停止确认时间 |
| REARM_MIN | 30 min | 两次自动开启最小间隔 |
| HEAT_MIN_MIN | 10 min | 单次最短加热 |
| HEAT_MAX_MIN | 180 min | 单次最长加热 |
| CLOUD_MIN | 10 ~ 180 min（默认 60） | 云端指令时长 |
| HEAT_W | 25 W/m | 低功率伴热 |
| FLOW_HYST | 0.06 m/s | 流速恢复回差 |

### 10.3 本地自动

```
持续低于阈值（温度 < 1 ℃ 或 流速 < 下限）≥ 3 min
        且 距上次自动停止 ≥ 30 min
                  ↓
              开启加热（25 W/m）
                  ↓
温度 > 3 ℃ 且 流速恢复，各持续 ≥ 3 min，且已加热 ≥ 10 min  → 关闭
或 已加热 ≥ 180 min → 强制关闭
```

### 10.4 云端指令

| 指令 | 行为 |
|---|---|
| 开启加热 | 按滑块所选时长（10 ~ 180 min）加热，期间本地阈值暂停；剩余时间以进度条递减；到期自动回落本地规则 |
| 关闭加热 | 立即停热并压制本地自动（表格显示「待机·云·禁」），直到「恢复本地」 |
| 恢复本地 | 清除云端指令，交还本地阈值控制 |

### 10.5 状态机

```
          ┌──────────── 待机（本地）────────────┐
          │  温度<1 或 流速<下限，持续3min       │
          │  且 距上次停止≥30min                │
          ▼                                     │
     加热中（本地）── 温度>3 且流速恢复(3min) ──┘
          │  ≥10min 才允许停；≥180min 强制停
          │
          ├── 云端「开启加热」→ 加热中（云端，倒计时）── 到期 ──► 待机（本地）
          ├── 云端「关闭加热」→ 待机（云端禁止）
          └── 云端「恢复本地」→ 待机（本地）
```

## 11. 变化速率分析

### 11.1 定义

```
速率 rate = (当前值 − k 次采样前的值) ÷ k      k = 5（≈5 模拟分钟）
温度速率单位：℃ / min
流速速率单位：(m/s) / min
```

采样点来自每个节点的 `history`（最多保留 40 点），因此速率是**滑动窗口**值，对单点抖动不敏感。

### 11.2 态势判定

| 态势 | 条件 |
|---|---|
| 回温中 | 正在加热 且 温度速率 > 0.05 ℃/min |
| 升温 | 温度速率 > 0.05 ℃/min |
| 降温 | 温度速率 < −0.05 ℃/min |
| 平稳 | 其余 |

### 11.3 展示

- 四张汇总卡：全网平均温度速率、全网平均流速速率、加热节点平均回温速率（仅统计已加热 ≥5 min 的节点，避免启动瞬间的负值误读）、升温最快 / 降温最快节点；
- 两条曲线：近 40 次采样的平均温度变化率、平均流速变化率（纵轴按数据自适应，零点居中）；
- 明细表：30 行，按 |温度速率| 降序，列出 温度 / Δ温度 / 温度速率 / 流速 / Δ流速 / 流速速率 / 态势，点击行联动选中。

### 11.4 用途

- **降温速率**反映环境与保温效果，可提前（而非到 0 ℃ 才）判断防冻风险；
- **回温速率**是伴热效果的直接指标：正常应在 0.5 ~ 1.5 ℃/min，明显偏低说明伴热带功率不足、保温层破损或传感器异常；
- 速率数据后续可入库，用于计算「单位时间温降」曲线与伴热能耗评估。

## 12. 一次刷新（tick）的数据流

```
setInterval(tick, settings.uploadMs)
  ├─ simMin += 1（1 次刷新 = 1 模拟分钟）
  ├─ 逐节点：环境漂移 / 随机突变 → 若加热中则叠加升温增益
  ├─ 计算 status（温度<1 或 流速<下限）
  ├─ stepHeat：更新 coldMin / warmMin / lowFlowMin / okFlowMin，
  │            处理云端到期、本地开关、10~180 min 时长限制
  ├─ history.push({t, temp, flow})，超过 40 点丢弃最旧
  ├─ 速率聚合 → rateAgg.push（保留 40 点）
  └─ renderAll：KPI / 拓扑 / 详情 / 表格 / 速率分析
```

刷新间隔由设置决定（默认 2 s），趋势图与速率窗口都以「采样次数」计，因此改频率不会破坏趋势语义。

## 15. 已知限制

1. 模拟器在浏览器：多个标签页各自独立，数据不共享；关闭页面数据即丢失（历史仅 40 点）。
2. 未接入真实设备，`/api/ingest` 未实现；云端指令目前只改前端状态，不下发。
3. 登录限流用进程内 Map，多实例部署会失效。
4. 遥测未落库，无法做跨天统计与导出。
5. 便携版 MySQL 不是 Windows 服务，机器重启后需手动双击 `启动MySQL.bat`。
6. 前端无自动化测试，回归依赖 `verify_api.js` + 人工用例。
7. 免密调试通道当前对所有人开放，上线前必须关闭。
